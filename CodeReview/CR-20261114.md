# Project review, 14 November 2026

Scope: the whole repository at `8217456`, eight months after the last review
(CR-20260307). Three changes were requested and made alongside the review:
isolating the GUI and web parts, refreshing the research notes, and moving the
knowledge graph onto HelixDB.

## Summary

The architecture is sound and the crate boundaries are sensible. The main
problem is that **the repository did not build or test cleanly as committed**,
so the test counts in the README and in ActionPlan-20260307 could not be
reproduced. Several bugs in the graph store had been hidden by that.

## What was changed

1. **GUI and web isolated** under `apps/`, excluded from the Cargo workspace.
2. **Research refreshed**: a sourced survey of agent-memory work from March 2025
   to November 2026, and a note mapping it onto this codebase.
3. **HelixDB graph backend**: a `GraphBackend` trait in `memst-core`, the
   existing JSON store behind it, a new `memst-graph-helix` crate, CLI support
   (`--backend`, `graph migrate`, `graph neighbors`), and a shared conformance
   suite. See `docs/graph-backend-helix.md`.

4. **Entity search** (added after the first pass): `search_entities` uses
   HelixDB's BM25 and vector indexes and falls back to MemSt's substring
   matching when HelixDB fails or finds nothing. CLI: `graph search`,
   `graph embed`.

The `KnowledgeGraph` API changed: every method now returns a `Result` and owned
values, and `get_entity_mut` is gone. This is a breaking change for any
external Rust caller.

## Suggested next steps

1. Get `cargo test --workspace` green (findings 3 to 6) and run it in CI, so the
   documented test counts are real.
2. Decide the evaluation plan in `docs/research/memst-and-the-field.md` before
   further work on the manuscript.
3. Embed entities automatically when they are extracted, and converge the
   three graph stores (finding 21).

# Addendum: sprint 1 (green build and CI)

Getting every crate to compile and every test to run exposed more defects.
The earlier per-crate table is superseded: `cargo test --workspace` now passes
(450 passed, 0 failed, 1 ignored, across 37 test targets), and the Python
binding tests pass (140 passed, 7 skipped).

## Bugs found and fixed

| # | Finding |
|---|---------|
| 26 | **WAL rotation closed stdin and aborted.** `WriteAheadLog::archive` swapped the current file for a zeroed `File`, which is file descriptor 0; assigning the new file then closed it. Any checkpoint or archive could abort the process. |
| 27 | **Worktree ids collided.** Ids were a millisecond timestamp, so two worktrees created in the same millisecond shared an id and the second silently replaced the first. |
| 28 | **Job ids collided** in the consolidation scheduler, for the same reason, losing scheduled jobs. The scheduler also queued jobs that were already finished and reported queue length as "queued". |
| 29 | **Fast-forward merges were never detected.** The ancestor check in `SemanticMerger::merge` had its arguments swapped. |
| 30 | **Contradictions were classified as support** in memory evolution: the "supports" test ran first and the leftover word overlap satisfied it. Negated restatements were also not found as neighbours at all, because "does not" pushed their similarity under the threshold. |
| 32 | **Entities without attributes could never be merged by default.** The attribute term was weighted in even with nothing to compare, capping similarity at 0.7 against a 0.85 threshold, so identically named entities were never proposed. |
| 33 | Four copies of the same word-overlap similarity (merge, consolidation, evolution, KG evolution), three of them case- and punctuation-sensitive. Now one module, `memst_core::text`. |

## Claims that did not match the code

| # | Finding | Status |
|---|---------|--------|
| 31 | **Three-way merge is not implemented.** `load_memories_at_commit` returns an empty list, so a non-fast-forward merge compares nothing. | **Open.** README corrected. |
| 34 | **The MCP adapter is a placeholder.** Every tool handler returns fixed text and none is connected to a store. | **Open.** README corrected; planned for the security and MCP sprint. |
| 35 | **The `duckdb` feature of `memst-extract-v2` never built.** Its backend returned "not implemented" for every call and the crate uses SQLite unconditionally. | Removed, along with an orphaned `db.rs`. SQLite is the only backend. |
| 36 | `memst-core` did not build with no search backend selected. | Now a clear compile error; both single-backend builds are checked in CI. |

## Tests that were wrong

About ten tests asserted things the code was never meant to do: similarity
thresholds that do not follow from the arithmetic, paraphrase recognition
without embeddings, confidence above its cap of 1.0, and a scheduler order that
is not first-in-first-out. Those tests were corrected; where a test described
semantic behaviour, it now supplies embeddings and exercises the embedding path.

## Added

- `.github/workflows/ci.yml`: workspace tests, feature combinations, Python
  bindings.
- `config.example.toml`, which the README referred to but did not exist.
