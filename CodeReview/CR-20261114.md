# Project review, 14 November 2026

Scope: the whole repository at `8217456`, eight months after the last review
(CR-20260307). Three changes were requested and made alongside the review:
isolating the GUI and web parts, refreshing the research notes, and moving the
knowledge graph onto HelixDB.

## Summary

The architecture is sound and the crate boundaries are sensible. The main
problem is that **the repository did not build or test cleanly as committed**,
so the test counts in the README and in ActionPlan-20260307 could not be
reproduced. Several bugs in the graph store had been hidden by that.

### Knowledge graph (`memst-core/src/graph`)

All fixed as part of the backend work, and now covered by a conformance suite
that both backends run.

| # | Finding |
|---|---------|
| 10 | `get_entity_mut` returned a reference into memory and nothing wrote the change back. Entity decay, deprecation, merge bookkeeping and access counts were lost when the process exited. Replaced by `update_entity`, which reads, changes and writes. |
| 11 | `KgDecayEngine::apply_decay` never decayed relationships; it only counted them. It now decays and persists both. |
| 12 | `get_relationship` discarded the stored decay fields and returned defaults. `find_relationships` and `all_relationships` returned relationships with freshly generated ids, so a result could not be used to update or delete the edge it came from. |
| 13 | `migrate_relationships` (used when merging entities) reset the decay state and stability of every edge it moved. |
| 14 | Every mutation rewrote the whole `graph.json` in place, with no temp-file-and-rename, so a crash mid-write could truncate the graph. The JSON backend now writes atomically. |
| 15 | Entity merge treated a failed relationship migration as a warning and reported success. It now returns the error. |
| 16 | `memst graph query --entity-type X --limit N` applied the limit before the type filter, so it could return fewer than N matches. |
| 17 | Test helpers in `kg_decay` and `kg_evolve` dropped their temp directory before using the graph in it. |

## What was changed

1. **GUI and web isolated** under `apps/`, excluded from the Cargo workspace.
2. **Research refreshed**: a sourced survey of agent-memory work from March 2025
   to November 2026, and a note mapping it onto this codebase.
3. **HelixDB graph backend**: a `GraphBackend` trait in `memst-core`, the
   existing JSON store behind it, a new `memst-graph-helix` crate, CLI support
   (`--backend`, `graph migrate`, `graph neighbors`), and a shared conformance
   suite. See `docs/graph-backend-helix.md`.

The `KnowledgeGraph` API changed: every method now returns a `Result` and owned
values, and `get_entity_mut` is gone. This is a breaking change for any
external Rust caller.

## Suggested next steps

1. Get `cargo test --workspace` green (findings 3 to 6) and run it in CI, so the
   documented test counts are real.
2. Decide the evaluation plan in `docs/research/memst-and-the-field.md` before
   further work on the manuscript.
3. Use HelixDB's vector and BM25 indexes for entity search, and converge the
   three graph stores (finding 21).
