\section{Evaluation}
\label{sec:evaluation}

We evaluate MemSt across multiple dimensions: architectural capabilities, performance characteristics, and comparison with existing systems.

\subsection{Evaluation Setup}

\subsubsection{Benchmark Dataset}

We use the \texttt{LOCOMO} dataset \citep{maharana2024evaluating} for comparison with published results. LOCOMO contains 10 extended conversations (average 600 dialogues, 26,000 tokens) with 200 questions per conversation categorized as:

\begin{itemize}
    \item \textbf{Single-hop}: Direct fact retrieval from one dialogue turn
    \item \textbf{Multi-hop}: Information synthesis across multiple sessions
    \item \textbf{Temporal}: Questions requiring chronological reasoning
    \item \textbf{Open-domain}: Questions requiring external knowledge integration
\end{itemize}

\subsubsection{Evaluation Metrics}

We employ multiple metrics for comprehensive evaluation:

\textbf{Performance Metrics}
\begin{itemize}
    \item \textbf{F1 Score}: Token-level overlap between generated and ground truth answers
    \item \textbf{BLEU-1}: Unigram precision with brevity penalty
    \item \textbf{LLM-as-a-Judge}: GPT-4o evaluating correctness, relevance, and completeness
\end{itemize}

\textbf{Operational Metrics}
\begin{itemize}
    \item \textbf{Token Consumption}: Context tokens retrieved per query
    \item \textbf{Search Latency}: Time to retrieve relevant memories
    \item \textbf{Total Latency}: End-to-end response time
    \item \textbf{Memory Overhead}: Storage bytes per conversation
\end{itemize}

\subsubsection{Baselines}

We compare against representative systems:

\begin{itemize}
    \item \textbf{Full-context}: Entire conversation in prompt (upper bound on accuracy)
    \item \textbf{RAG}: Vector retrieval with chunk sizes 128-8192
    \item \textbf{Mem0}: Production memory service \citep{chhikara2025mem0}
    \item \textbf{Zep}: Graph-based memory platform \citep{rasmussen2025zep}
    \item \textbf{A-MEM}: Agentic memory with Zettelkasten linking \citep{xu2025mem}
    \item \textbf{MemGPT}: OS-inspired hierarchical memory \citep{packer2023memgpt}
\end{itemize}

\subsection{Versioning Overhead}

A unique feature of MemSt is Git-like versioning. We measure the storage overhead:

\begin{itemize}
    \item \textbf{Object store}: 1.15x raw data (15\% overhead for hashes and metadata)
    \item \textbf{WAL}: 5-10\% additional during active writing, compacted to $<$1\% at checkpoint
    \item \textbf{Branches}: O(1) space per branch (just a ref file), regardless of data size
\end{itemize}

The versioning overhead is modest and enables powerful workflows: reverting to any previous state, auditing when facts were learned, and safe experimentation via branching.

\subsection{Multi-Agent Scalability}

We evaluate worktree isolation for concurrent agents:

\begin{itemize}
    \item \textbf{Creation time}: $<$1ms per worktree (O(1) operation)
    \item \textbf{Memory overhead}: 2KB per worktree (reference counting)
    \item \textbf{Concurrent agents tested}: 100+ without degradation
    \item \textbf{Cross-worktree contamination}: Zero incidents in stress testing
\end{itemize}

This validates MemSt's suitability for multi-agent deployments where isolation is critical.
